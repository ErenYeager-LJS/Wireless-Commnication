# 手机配网验证记录 · 2026-11-22

本次修改在 `integrations/esp-firmware/` 中完成。原局域网工程没有改动，也没有继续修改公网播放链路。两套应用均用 ESP-IDF 5.5.1 构建成功，已分别通过 COM14 和 COM12 烧录，esptool 写入哈希校验通过。仅更新应用分区，保留引导程序、分区表和 NVS；更新前的 NVS 备份在本项目 `buffer/provision/`。

## 已完成的检查

- C 策略测试通过：SSID／密码的字节边界、开放网络、64 位 PSK、同名密码替换、最近成功网络优先、6 条容量和损坏记录检查。
- 页面在 Edge 的 320、375、414、768 像素宽度下无横向溢出；测试了中文名称提交、密码长度校验、连接期间禁用按钮、成功后清空输入框，以及网络名称按文字显示、不当作 HTML 执行。截图在 `buffer/provision/ui/`。
- 电脑作为 Wi-Fi 客户端，实际连接摄像头和中继的设备热点，读取本地配网页面、提交配置。无效令牌、跨站来源和不合法密码均被拒绝。测试中临时创建的电脑 Wi-Fi 配置已删除，电脑恢复连接 `Tenda_LJS`。
- 两块设备连接不存在的网络后，没有修改原存储记录，配网入口仍可用；提交正确网络后，实际获得上游地址。中继已确认将记录写入 NVS，重启日志读回 1 条用户网络。
- 摄像头完整流程通过：开机窗口、页面访问、无效请求拒绝、连接失败不覆盖记录、正确网络连接、重启读回记录、30 秒后自动连接、关闭临时配网热点。重启后的日志确认恢复 OV5647 1280×720 H.264 发送，并重新建立云端 TLS 连接。
- 通过匹配证书的公网 HTTPS 检查，摄像头云端接收计数从 133044 增至 133269，三次采样均为真实 1280×720 直连画面、无线控制在线。这里只确认接收恢复，不把云端接收帧率当成浏览器播放帧率。

## 中继供电仍有故障

中继的热点访问和网络保存已实际成功，但后续重启检查反复出现 `Brownout detector was triggered`。欠压发生在无线启动附近，导致这轮中继重启自动恢复检查无法完整结束。保留了欠压保护，没有通过关闭检测掩盖故障。需要换稳定的供电线／电源后复测，不能把当前中继描述为已通过连续稳定运行验收。

中继热点沿用原来的密码，摄像头查找中继时也沿用这个密码，保持新旧固件之间的连接兼容性。
