目标服务器为腾讯云上海 Windows Server 2025，公网 IP `101.43.11.188`，按 **2 核 2 GB** 配置。用户目前通过 VNC 登录，因此本轮交付上传包；未取得远程命令行连接，也未在该服务器执行安装、开放端口或完成公网实板验证。

## 先拿这三个包

| 文件 | 用途 | 放在哪里 |
| --- | --- | --- |
| `Wireless-Cloud-Server-20261122.zip` | 已构建网页、编译后的 Node 后台、Python 接收器、安装脚本 | 上传服务器并解压到安装目录 |
| `PRIVATE-Server-Config-20261122.zip` | 本次部署证书私钥、设备密钥和登录资料 | 上传同一服务器，解压到同一安装目录；不要公开分享 |
| `PRIVATE-Cloud-Firmware-20261122.zip` | 摄像头 P4 和中继 ESP32 的匹配固件 | 留在现场电脑烧录；包含 Wi-Fi 和设备凭据，不要公开分享 |

`SHA256SUMS.txt` 用于核对文件。普通服务包不含私钥、Wi-Fi 密码、模型和 `node_modules`。两个 PRIVATE 包只用于你自己的设备和服务器。服务包与配置包合并后应出现 `deploy/private/cloud.json`。

## 服务器首次安装

1. 用 VNC 控制台提供的文件上传功能（若有），或你已有的可信文件传送工具，把前两个 ZIP 传到服务器。VNC 是否支持文件传输取决于当前控制台；本轮没有代为上传。
2. 解压到你选择的同一个目录，例如系统盘的 `WirelessCloud`。无需服务器有 E 盘。下文用 `$CloudRoot` 指代该目录。安装缓存和日志也放在该目录内。
3. 打开**管理员 PowerShell**，执行：

```powershell
$CloudRoot = Join-Path $env:SystemDrive 'WirelessCloud'
Set-Location $CloudRoot
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Install-Cloud.ps1
```

若需要在 PowerShell 解压，把下面的 ZIP 路径替换为服务器上的实际路径：

```powershell
$CloudRoot = Join-Path $env:SystemDrive 'WirelessCloud'
Expand-Archive -LiteralPath '服务包的实际路径.zip' -DestinationPath $CloudRoot
Expand-Archive -LiteralPath 'PRIVATE配置包的实际路径.zip' -DestinationPath $CloudRoot -Force
```

安装器验证 Python、Node 和 SQLite，建立项目虚拟环境，安装 PyAV、无界面 OpenCV、psutil 和 Node 生产依赖；不安装 ONNX Runtime，不下载模型。它使用包内已构建的网页和 Node JS，不要求服务器安装 Git 或运行前端构建。已报告的云端 Python 3.12.10、Node 26.13.1 尚未远程复核；本地测试使用 Python 3.12 与 Node 24。若版本检查或依赖安装失败，先看错误，不要直接升级实例。

Python／Node 找不到时，用真实可执行文件路径重试：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Install-Cloud.ps1 `
  -PythonExe 'Python安装目录\python.exe' -NodeExe 'Node安装目录\node.exe'
```

安装器注册 `WirelessCommunicationCloud` 开机计划任务，以 **SYSTEM** 运行监督进程，自动拉起接收器和网页服务。计划任务不依赖交互登录会话；不过云端 VNC 断开、用户注销和重启的实测仍必须完成，不能把这个配置当作已经验收。

## 只开放这三个业务端口

| 方向、协议、端口 | 用途 | 来源建议 |
| --- | --- | --- |
| 入站 TCP 443 | HTTPS 登录、页面、MJPEG、WebSocket、网页控制 | 自己的观看网络；手机网络不固定时可放宽，仍须登录 |
| 入站 TCP 8443 | P4 发起的 TLS H.264 连接；直连和中继最终都到此端口 | 现场路由器公网出口 IP，若出口动态则按需放宽 |
| 入站 UDP 8081 | 设备发起的 HMAC 签名心跳和控制回执 | 同一现场公网出口 IP，若出口动态则按需放宽 |

**腾讯云轻量应用服务器的防火墙**和**Windows Defender 防火墙**是两层规则，必须都允许最终使用的三个端口。安装器只设置 Windows 的上述业务规则，不会修改腾讯云控制台。不要使用全端口放行，不需要公开 8080、8787、1883 或 ESP 的现场私网地址，也不要因此修改已有 VNC/RDP 管理规则。

内部 Python HTTP 只绑定 `127.0.0.1:8080`，承载状态、MJPEG 和管理接口。云端没有局域网广播发现服务。443 的视频、API 和 WebSocket 均要求登录；控制还检查页面来源。8443 要求匹配的设备令牌，8081 校验 HMAC、启动标识和序号，拒绝未签名、篡改或重放的数据。中继只转发摄像头到云端的 TLS 字节，不解密图像。

现场出口固定时可重装规则并收窄 Windows 来源，例如：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Install-Cloud.ps1 `
  -SkipDependencies -SiteSources '现场公网IP/32' -ViewerSources '你的观看公网IP/32'
```

腾讯云控制台的来源规则也应相应收窄。出站需要 HTTPS 下载依赖、设备到云端的 TCP 8443／UDP 8081；现场 P4 使用 SNTP 校时，构建时间作为冷启动时钟下限。

## HTTPS 证书和首次登录

当前没有域名，交付了绑定 `101.43.11.188` 的专用自签名证书。设备固件信任本次证书，**没有跳过 TLS 服务端校验**。浏览器首次访问可能提示证书不受信任：先用私人资料中的 SHA-256 指纹核对证书，再将仅有公钥的 `deploy/private/server-cert.cer` 导入自己观看设备的信任存储。安装目录里的 `LOGIN-PRIVATE.txt` 含用户名、密码和指纹，不要截图分享或提交仓库。不要把 `server-key.pem` 传给观看者。

Windows 观看电脑可以导入当前用户的受信任根证书；手机需要按系统的证书安装流程设置。若手机浏览器不允许自签名证书的 WebSocket，须先完成证书信任，不能关闭客户端证书验证来掩盖。更换公网 IP、证书或设备密钥，需要重新生成匹配配置并重编／重刷 P4。公开运营前应换用自己的域名与公开可信证书，并向腾讯云核对大陆节点的备案要求；本轮没有代办备案或购买域名。

浏览器打开：`https://101.43.11.188/`。使用 PRIVATE 配置包中的账号密码登录，页面右上有“退出登录”。会话有效期八小时，Cookie 为 Secure、HttpOnly、SameSite=Strict；重启网页服务后需重新登录。默认只允许两路同时观看，避免过多 MJPEG 下载占用带宽。

## 现场设备

先完成服务器安装和云平台规则，再按《固件烧录与回退.md》给 **P4 摄像头板和 ESP32 中继板**分别烧录云端固件。板载 C6 继续使用原来匹配的 ESP-Hosted 2.2.3，本轮不刷 C6。云端二进制已编译，但本轮没有刷到实板。

```text
直连：P4/C6 → 主路由 → 云端 TLS 8443
中继：P4/C6 → 中继 TCP 8082 → 主路由 → 云端 TLS 8443
控制：P4 → 当前 AP／NAT → 云端签名 UDP 8081 → 原连接返回指令
观看：手机／电脑 → 云端 HTTPS 443 → MJPEG
```

云端地址固定写为 `101.43.11.188`，不依靠广播发现，也不需要路由器端口映射。控制由相机持续主动轮询，关闭视频后仍保留心跳。保留现有自动选路、手动直连／中继、相机开关、180°旋转和圆周飞行示意。RSSI 仍参考当前连接的 AP，不是实测距离；帧号缺失率仍不等于 Wi-Fi 丢包率。

## 公网延迟与资源

视频仍由 P4 硬编 **1280×720 H.264、目标约 1.2 Mbps**，云端 PyAV 真正解码后再 ACK。云版根据观测到的 ACK 时间在 4～8 帧间调整窗口；发送预算 1.6 秒、ACK 上限 2 秒，队列图像超过 750 ms 后重置参考链。GOP 缩短为 15，重连仅从完整 IDR 开始。TLS 首次握手较慢时保留连接，丢弃过期 GOP 等下一张新 IDR，避免反复握手积压。中继连接超时和转发预算相应放宽。

不能无限等待来维持假在线：断图两秒后页面撤销实时标识和旧检测框。不会通过重复旧帧增加接收帧率。公网 RTT、云端实际带宽及浏览器下载能力尚未测量，720p／30 fps 是目标，不是本轮云端成绩。

云端先关闭人物推理，启动不导入 ONNX Runtime 或加载模型，网页尝试启用会给出明确提示。完整检测源码保留在项目，原局域网模式仍可用。2 GB 服务器如需启用，应先核实剩余内存、安装额外依赖并单独测试；不要直接复制本机大模型启动参数。

浏览器继续使用 MJPEG，三维场景在观看者设备渲染，服务器不需要 GPU。**MJPEG 下载码率会高于 1.2 Mbps H.264 上传码率**，须用实际字节数评估带宽。若受限，先减少观看数或降低显示 JPEG 质量；不要把画面缩小再放大冒充原生高清。后续可再评估 H.264 直通播放器，不把未经验证的 WebRTC 当作已完成。

## 健康检查、常驻、日志与停止

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Health-Cloud.ps1
```

检查计划任务是否 Running、443 和 8443 是否监听，以及 Python 8080 是否只绑定回环。`data/health.json` 每两秒记录两个子进程的 CPU、RSS 内存和视频状态；资源数字来自运行实例，不能用本地测试替代云端资源报告。`logs/receiver.log`、`web.log`、`supervisor.log` 每个最多 5 MiB，保留三个历史副本。出现错误先发不含密钥的日志，不要发送 PRIVATE 配置文件。

停止、重新启动和卸载：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Stop-Cloud.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Start-Cloud.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\deploy\Uninstall-Cloud.ps1
```

停止只处理本项目监督的两个子进程。卸载删除本项目计划任务及 Windows 业务规则，保留源码、配置和日志；不改云平台规则，不删除其他程序。停止后留有标志文件，再次运行 Start 会清除。不要在服务运行时覆盖密钥或固件配置。

```powershell
.\.venv\Scripts\python.exe -B .\deploy\measure_cloud.py --seconds 300 --output .\logs\cloud-relay-5min.json
```
