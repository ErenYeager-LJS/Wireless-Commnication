# 云端固件烧录与回退

先安装云端服务并核对 443／8443 TCP、8081 UDP 规则，再刷现场固件。当前交付版本绑定 `101.43.11.188` 和同批 PRIVATE 配置；换证书、地址或设备密钥必须重新编译。

本轮已完成编译，未识别或刷写当前实板。重新枚举串口，不能照抄历史 COM 号。P4 摄像头主控对应 CAM，经典 ESP32 中继对应 Repeater；板载 C6 不动。

在现场电脑解压 `PRIVATE-Cloud-Firmware-20261122.zip`。安装 esptool 5.x（可沿用原工程工具环境）。进入固件包目录，用对应串口执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Flash-Cloud.ps1 -Project Repeater -Port COM实际中继号 -PythonExe 'python的实际路径'
powershell -NoProfile -ExecutionPolicy Bypass -File .\Flash-Cloud.ps1 -Project CAM -Port COM实际P4号 -PythonExe 'python的实际路径'
```

烧录脚本先校验包内 SHA-256，再按清单写入 bootloader、分区表和应用。不要写空白分区或执行全片擦除，不要把 C6 应用刷到 P4 USB 口。云版 P4 使用 16 MB Flash、0x2000 bootloader、0x10000 应用；中继为经典 ESP32、4 MB Flash，仍以清单为准。

烧录后保持两块板独立稳定供电、现场路由器联网。在云端页面依次测试直连、中继、暂停后切网再恢复、自动模式。若无法注册，先检查设备出站网络、两层防火墙和服务器的 receiver.log；不要通过关闭 TLS 校验排查。P4 日志里的 `Authenticated cloud TLS` 表示 TLS 和 HTTP 设备认证通过，`decoded_ack_fps` 才是实际解码回执速率，两者不能互相替代。

原局域网工程 `E:\Agent_workplace\esp_image_relay_demo` 未改，原固件仍在 `Soft\firmware\CAM`、`Soft\firmware\Repeater`。要回退，在原工程根目录使用原有脚本与 `--release`，分别刷回两块板，再启动原局域网接收器：

```powershell
python -B Soft/tools/flash.py Repeater --port COM实际中继号 --release
python -B Soft/tools/flash.py CAM --port COM实际P4号 --release
```

云端与局域网固件分别保留，不能只回退网页而让设备仍发往云端。不要在确认云端真视频前删除原固件。二进制含 Wi-Fi 和设备认证信息，仅限本人的私有设备使用。

源代码在网页工程 `integrations/esp-firmware`，私有生成头文件已被 Git 忽略。它复用原工程经过验证的摄像头／SDIO／Wi-Fi 配置与 vendor 组件。可通过 `deploy/Build-Firmware.ps1` 重编，构建产物在本项目 `buffer/cloud-firmware-*`。本机 P4 编译使用了临时 Q: 盘短路径以避开工具链长路径问题；该映射不会用于云端运行，SDK 本身未修改。
