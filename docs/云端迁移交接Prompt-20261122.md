## 必须保留的现有功能

硬件为慧勤智远 ESP32-P4 CB V1.2，板载 C6，CSI 接口连接 OV5647，另有一块 ESP32 中继板。只保留 OV 单摄像头，奥尼 USB 摄像头相关功能已移除，迁移时不要重新引入双摄。

沿用现在的 UI 和园区场景，包括建筑材质、道路绿化、灯光阴影、可折叠侧栏，以及以下功能：

- 自动／直连／中继的网页无线切换，日常操作不依赖 COM 串口。
- 摄像头开关、画面放大和 180°旋转。
- 帧率、帧号缺失率、当前路径和 RSSI；帧号缺失率不能标成 Wi-Fi 丢包率。
- 断图时清除在线标识和过期人物框，不能把停住的旧画面当作实时画面。
- 人物框选功能保留，但云端第一阶段先关闭推理，避免占满 2 GB 内存。
- 无人机保持较高高度的圆周运动，信号改变时平滑调整半径；RSSI 仅作示意，不是实测米数。直连的参考是主路由，中继的参考是中继 AP。

三维场景由观看者的浏览器渲染，不需要在云端运行带桌面的浏览器或专门购买 GPU。云端负责接收、转发、状态和控制；人物检测启用时也在接收侧处理。

## 当前链路及迁移难点

根据当前说明文件，主视频链路是持续 TCP 传送 H.264 access unit，接收端解码、核对宽高后返回确认。**不能把历史 UDP-FEC 接收兼容逻辑当作当前主视频链路。** 实施前仍要核对正在使用的固件和集成副本是否一致。

```text
直连：P4／C6 → 主路由 → 本地电脑 TCP 8080
中继：P4／C6 → DEMO_RELAY TCP 8082 → 主路由 → 本地电脑 TCP 8080

UDP 8081：局域网发现、设备心跳、无线控制
Python：H.264 解码、MJPEG 输出、状态、人物检测
Node TCP 8787：集成网页与接收桥，目前按本机方式使用
```

原固件说明中的初始参数为 1280×720、H.264 目标码率约 1.2 Mbps，最多 6 帧等待解码确认。码率、窗口、超时和实际版本应重新核对，公网延迟可能改变吞吐表现。现有网页通过 MJPEG 播放；云端带宽评估不能只用 H.264 上传码率代替浏览器下载码率。

现场主路由目前使用 Tenda_LJS 的 2.4 GHz 网络。原工程包含备用 Wi-Fi 配置，私有凭据在本地配置文件中，不要把密码写进交接文档、日志或发布到 GitHub。串口号是易变信息，刷写前重新枚举。

局域网广播发现不能跨公网使用。迁移需要调整摄像端和中继端对接收地址的获取方式，并让控制链路通过设备主动建立或维持的出站连接工作，考虑路由器和中继的 NAT。云服务器无法直接访问现场 `192.168.*` 地址。

当前接收端说明涉及本机控制限制和未认证的局域网设备控制。不要仅把监听地址改成 `0.0.0.0`、直接公开原有控制接口就当作部署完成。对外网页需要身份验证；视频、控制接口和管理接口要明确访问边界，设备侧连接需要校验身份。若使用 WebRTC，需一并考虑 HTTPS、信令、NAT 穿透及可能的 TURN 流量，不能只接入播放器。
