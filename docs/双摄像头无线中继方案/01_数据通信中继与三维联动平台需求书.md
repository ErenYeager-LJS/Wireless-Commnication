# 数据通信中继与三维联动平台需求书

> 主项目｜开发周期：7 个自然日｜交付形态：打印外壳实物成品＋可真实联动的三维网页。

## 一、项目整体方案设计

### 1.1 项目目标

面向园区地下空间、走廊或设备遮挡场景，开发一套单跳数据通信中继系统：终端与控制端直连不稳定时，通过中继节点恢复数据传输，同时在三维园区中展示故障位置、实际通信路径、业务恢复及远程控制结果。

本周交付为可重复演示的工程样机，不要求量产级产品。核心是**真实中继、真实数据、实物与网页同步变化**，不以预录视频或预设动画替代通信效果。

### 1.2 建设范围

- 必做：1 个业务终端、1 个中继节点、1 台控制电脑；必要时增加控制端网关。
- 必做：单跳双向通信，支持人工选择直连／中继，断线后自动重连。
- 必做：现场图像、环境量或告警按钮、远程警示灯、真实链路测量及三维联动。
- 加分：自动选路与切换、多终端接入、事件回放。
- 本周不做：自研 PCB、多跳 Mesh、高清多路视频、实时室内定位、AI 模型训练、工业防护及量产认证。

## 二、核心价值与展示效果

1. **通信保障可验证**：同一场地对比直连和中继的丢包、延迟与有效速率。
2. **故障恢复可理解**：三维场景定位失联终端，切换后显示新路径和恢复耗时。
3. **业务控制有闭环**：网页发出灯控指令，远端实物动作并返回执行确认。

三分钟演示流程：园区全景 → 抽出地下层 → 终端告警 → 直连退化或失联 → 启用中继 → 路径亮起、画面与数据恢复 → 远程点亮警示灯 → 展示实测对比结果。人工启用须明确标注，不包装为自动切换。

## 三、系统整体架构

```text
业务终端                         中继节点                    控制端
摄像头／传感器／按钮／警示灯 ←→ 接收、转发、重连与测量 ←→ 控制电脑或本地网关
                                                               ↓
                                                本地数据服务与消息服务
                                                   ↓           ↓
                                              状态和事件存储  三维网页
```

实际部署需同时支持直连和中继两种测试模式。架构图中的双向箭头代表逻辑数据流，开发者须在第 1 天给出实际网络拓扑、IP 分配、转发方式和切换方式，避免仅有 AP＋STA 连接却未完成端到端转发。

| 层级 | 职责 | 输入与输出 |
|---|---|---|
| 业务感知层 | 采集现场图像、环境量和告警，执行灯控 | 业务数据、命令执行回执 |
| 通信中继层 | 双向转发、连接维护、状态上报 | 数据包、上下游状态、转发计数 |
| 数据服务层 | 接入设备、计算指标、下发命令、记录事件 | 标准化设备状态、链路指标、事件 |
| 数字孪生层 | 空间映射、路径展示、设备点选、状态着色 | 由真实状态驱动的三维场景 |
| 应用交互层 | 实时画面、告警定位、控制操作、效果对比 | 可操作的演示大屏 |

平台消息服务只是管理与展示通道，不等同于中继机制。验收业务必须经过被测中继，不能通过另一张网卡、云服务或备用连接绕过。

## 四、硬件选型与成品要求

### 4.1 推荐硬件组合

| 模块 | 推荐方向 | 要求 |
|---|---|---|
| 中继节点 | 现货 Linux／OpenWrt 网关或成熟无线转发模块 | 支持实际双向转发和状态读取；双无线电优先，具体型号首日冻结 |
| 业务终端 | ESP32 摄像头板或现有 Linux 摄像头终端 | 接入图像、传感器／按钮、警示灯；以现货与资料完整为先 |
| 控制端 | Windows 电脑，必要时增加接入网关 | 支持本地服务和浏览器，不依赖公网 |
| 外围与供电 | 环境传感器或告警按钮、LED 灯、USB 电源 | 至少一种上行业务与一种下行控制有实体效果 |

如采用单无线电 AP＋STA，须首日验证同信道、驱动支持、转发能力和图像带宽。开发者可替换推荐器件，但须提供理由、成本和首日验证结果。

### 4.2 外壳与装配

终端和中继均需安装 3D 打印外壳，交付至少两台装配成品。要求固定可靠、无松散飞线，保留供电、天线、指示灯及散热位置；标明节点角色、编号和接口。优先 USB 供电，不强制电池与防水。第 2–3 天完成结构定稿并送印，预留返工时间。

## 五、技术选型与核心功能

### 5.1 推荐技术栈

| 部分 | 技术选型 | 实施原则 |
|---|---|---|
| 无线链路 | Wi-Fi；路由／桥接或应用层转发 | 首日确定唯一主方案；不要求兼容任意无线制式 |
| 终端程序 | ESP-IDF C／C++ 或 Linux 程序 | 心跳、序号、命令回执、重连，避免无界缓存 |
| 本地后端 | Node.js＋TypeScript，或团队熟悉的 FastAPI | 负责接入、指标、事件、控制；不同时维护两套后端 |
| 状态与控制 | 本地 Mosquitto MQTT＋WebSocket | 图像单独传输；告警与控制优先 |
| 前端 | Three.js＋TypeScript；可配 Vue 3／React | 可复用已有三维场景，具体框架首日冻结 |
| 存储与部署 | SQLite／结构化日志、Windows 启动脚本 | 无公网依赖，提供锁定版本与完整安装说明 |
| 结构设计 | FreeCAD／Fusion 360 等 | 提供可编辑模型、STEP 和 STL |

### 5.2 数据与控制要求

- 图像必须来自现场设备；首选连续低码率视频，保底为每秒至少 1 帧实时图片。首日确定分辨率、帧率和码率预算，网页显示实际帧率及数据时间。
- 至少上传一种真实环境量或按钮告警；警示灯支持远程开关。
- 设备状态至少每秒更新一次，包含编号、角色、在线状态、上下游、当前模式和最后更新时间。
- 链路显示 RTT、丢包、有效速率；RSSI 仅在硬件可读取时展示，不以其替代业务质量。
- 控制命令带唯一编号、目标、动作和超时，返回终端执行结果；命令重复接收不得造成重复动作。MQTT 收到消息不等于设备执行成功。
- 断连标记离线并保留最后时间；恢复后刷新状态，不能把旧画面和旧指标持续标成实时。

### 5.3 三维平台要求

参考 `cybereye_system/my园区数字孪生中枢.html`，保留建筑全景、楼层抽出、透明化、设备点选和告警定位；围绕通信主题整理界面，不要求沿用其他固件项目。

中央突出建筑、终端、中继和实际路径，两侧展示实时画面、链路指标、事件与控制。正常绿、退化黄、失联红；状态规则和阈值配置化，首日约定采样窗口与离线超时。路径按实际模式、上下游及转发证据更新，未知时显示未知，不能只凭“中继已上电”点亮路径。

支持 1920×1080 全屏；重点数据和故障提示大屏可读。实测、模拟与历史数据显著区分。位置允许人工配置；区域覆盖只能展示实测点或明确标注的估算。三维模型可简化，不要求真实 BIM、AR 或高精度测绘。

## 六、模块接口与部署方案

| 接口对象 | 最小字段／内容 |
|---|---|
| 设备状态 | `node_id`、角色、时间、序号、在线状态、上／下游、当前模式、最后接收时间 |
| 链路指标 | 源／目标、路径、采样窗口、发送／接收／超时数、RTT、有效字节数、数据来源 |
| 业务数据 | 设备编号、时间、数据类型、数值／告警、图像地址 |
| 控制与回执 | `command_id`、目标、动作、发送时间、执行状态、错误原因 |
| 事件 | 时间、对象、事件类型、前后状态、恢复耗时、关联测试编号 |

指标区分不同路径和测试轮次。小数据使用带序号的探测包；RTT 由同一端计时，不用两台未同步时钟计算单向延迟。有效速率按窗口内实际收到的业务字节统计，不把无线协商速率当作吞吐量。

网页、依赖资源、字体、消息服务和存储全部本地化。交付 Windows 启动与停止脚本、网络配置表和排障说明；设备上电自动启动程序。断开互联网后，整套系统仍能演示。

## 七、技术分工与七天推进

建议硬件通信与前端至少各 1 人并行承担；服务集成、结构打印和验收责任须明确。

| 时间 | 任务 | 当日检查成果 |
|---|---|---|
| 第 1 天 | 冻结拓扑、器件、接口、场地及测试口径 | BOM 与报价；实机转发及图像验证；风险与替代器件 |
| 第 2–3 天 | 完成转发、探测、灯控、本地服务；整理三维场景；外壳送印 | 端到端数据及回执、接口样例、打印文件 |
| 第 4–5 天 | 网页接真实设备，实现路径、告警、视频和事件 | 可完成一次真实闭环演示 |
| 第 6 天 | 装壳、离线部署、稳定与异常测试 | 两台成品、测试日志、缺陷清单 |
| 第 7 天 | 修复、三轮演示、代码与资料移交 | 完整交付包及签收记录 |

所有硬指标为本次样机验收目标，不是已取得的性能。若首日发现不可达，须提出替代方案和变更清单，经双方确认后冻结，不能在最终验收时自行降低要求。

## 八、测试验收与最终交付

| 验收项 | 通过条件 |
|---|---|
| 中继实际生效 | 提供两种模式的拓扑、转发计数及接收记录；关闭中继后，中继模式业务中断，排除备用链路绕行 |
| 遮挡点收益 | 同位置、同设备、同负载分别测试 60 秒；直连丢包 ≥20% 或不能通信，中继后丢包 ≤1%；记录距离、障碍和摆放，不承诺通用覆盖距离 |
| 小数据延迟 | 128 字节探测包，每秒 10 包；图像同时开启，中继模式 RTT 的 P95 ≤200ms；分别统计超时、重复与有效包 |
| 恢复及界面 | 上游恢复后 10 秒内重连；状态变化后 2 秒内更新网页；10 次灯控均取得执行确认，单次超时为 3 秒 |
| 稳定与图像 | 连续运行 1 小时无需重启；至少三次断连恢复；现场图像达到首日冻结参数及至少 1 帧／秒保底 |
| 成品与演示 | 两台打印外壳成品；Windows 无公网可运行；连续完成三轮三分钟实物联动演示 |

自然遮挡难以复现时，可另做明确标注的受控断链测试，验证恢复逻辑；该测试不能替代遮挡条件下的覆盖收益验证。指标不得用模拟数据或录屏验收。

交付清单：装壳硬件与线材、BOM 及成本、接线和拓扑图、完整源码与版本锁定、固件／配置、接口说明、Windows 部署包、外壳源文件及 STEP／STL、打印参数、原始测试日志、验收报告、三分钟演示脚本及录像。首日报价分列物料、打印、开发与测试费用。

## 九、后续拓展方向

在本周闭环稳定后，再评估自动选路、多终端、多跳网络、高清图像、4G／5G 出口和低速远距链路。射频信号中继作为独立项目，采用单独技术路线、预算和验收，不与本项目混合交付。
