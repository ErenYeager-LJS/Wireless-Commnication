# OV5647 实时画面接入三维平台

本次接入使用现有 ESP32-P4/C6、OV5647 和一块 ESP32 中继。原仓库的园区、楼层抽出、透明化、设备点选、动态无人机继续保留，视频与状态面板改为接收这套实物的数据。原有 MQTT／模拟模式仍可从各自入口启动。

## 启动与使用

电脑连接 Tenda_LJS 的 2.4 GHz 局域网，两块 ESP 保持供电，双击根目录 `启动OV高清中继平台.cmd`，打开 `http://127.0.0.1:8787`。开发依赖首次安装后，局域网传图无需互联网。该入口先检查／启动 Python 接收端，再启动 Node 桥接服务，不需要串口，也不会重新烧录设备。

画面在左侧，按原要求旋转 180°；右上角可放大，按 Esc 或收起按钮返回。人物框随实际显示区域缩放，检测过期、断图或暂停后隐藏。人物框选开关只控制电脑上的推理，不关闭摄像头。

字体调整后，主要文字为 14～16 px，多数辅助说明为 13 px，三维标签不再随摄像机距离缩小。视频链路详情、路径对比、设备状态、硬件和事件可点击标题展开；两侧边缘的箭头可收起整栏，三维视口会自动扩大。手机端保留各项折叠标题。

OV 模式将摄像端映射为 UAV-01，并按最新需求使用 RSSI 控制圆周飞行半径。直连时围绕右侧接收楼飞行，中继时围绕中间中继器飞行；信号越弱，半径越大。稳定半径下按固定线速度飞行，RSSI 变化时平滑调整半径，不重置飞行相位。场景飞行高度从 10 提高到 18，均为示意坐标，不表示实测米数。楼层抽出时，中继与接收节点仍随各自楼顶升高。

RSSI 只用于相对位置示意，不换算米数，也不替代硬件的自动切换算法。连接中继后上报的是中继 AP 的 RSSI，不能解释为到主路由器的距离，因此改以中继节点为圆心。半径使用连续映射，修正了旧映射将高于 −40 dBm 的信号压到同一位置的问题，−33／−35 dBm 这类强信号变化也会改变半径。图像连线依据真实收到的路由元数据改变，渲染位置本身不发送切网指令；断图时停止飞行与流动光点。

右侧可选择自动、直连、经中继，也可暂停／开启画面。指令通过 Wi-Fi 发送。换网会短暂断图，按钮等待 ACK 和换网后的新心跳再解除忙碌状态；当前路径以实际收到的图像为准。暂停状态下仍可换网，此时保持“无图像路径”的提示，重新开启画面后才点亮路径。

停止平台可运行 `停止平台.cmd` 或 `scripts/Stop-Platform.ps1`。停止脚本只停止它记录的 Node 与接收进程；启动时复用的外部接收程序不会被停止。如果其他模式已经运行，先停止再使用 OV 入口，避免误将模拟页面当作实物页面。

## 数据与边界

| 页面内容 | 数据来源／含义 |
| --- | --- |
| 720p 画面 | ESP 硬件 H.264 → Python 解码 → Node 转发 MJPEG |
| 接收帧率 | 接收程序统计，与人物推理 Hz 分开 |
| 帧丢失率 | 最近 3 秒编码帧号缺失比例，不等于 IP 或 Wi-Fi 丢包率 |
| RSSI、网络名称 | 收到的摄像头路由元数据 |
| 电脑解码时间 | H.264 解码统计，不能解释为端到端延迟 |
| 人物框 | 电脑 YOLOX／ONNX 推理；旋转后坐标与画面一致 |
| 直连／中继对比 | 各路径最近一次实测样本，非同时对照实验，悬停可查看采样时间 |
| 中继在线 | 仅收到中继路径图像时确认正在转发；直连时显示“未确认转发” |
| 三维园区、无人机、设备位置 | 示意模型，未接入定位／无人机硬件 |

没有采集的网络 RTT、温湿度、警示灯数据不在 OV 模式显示。平台 WebSocket 中断或接收状态超过两秒没有更新时，画面、LIVE 标识和人物框失效，不保留旧数据冒充实时状态。人物识别存在误检／漏检，不能作为可靠人数统计。

三维动画在 OV 模式随浏览器的刷新节奏更新，保留单倍像素比、1024 阴影贴图，并避免随每次视频统计重建场景。相机初始配置保持稳定，不因每次 RSSI 更新重置。放大视频或页面进入后台时停止主动场景刷新，保留资源用于视频解码和推理。原有模拟模式保留原渲染设置。

## 接入结构

```text
P4 / OV5647 ── C6 ────────────── 路由器 ── 电脑 Python :8080
                  └─ ESP32 中继 ───┘          │ H.264 解码 / 人物检测
                                             ▼
浏览器 React / Three.js ◀── Node :8787 ◀── 状态、MJPEG、检测框
        └── 自动 / 直连 / 中继 / 暂停 ──▶ Python ── Wi-Fi ACK ──▶ ESP
```

Node 的 `PLATFORM_BACKEND=esp32` 模式连接本机 `ESP_RECEIVER_URL`，默认 `http://127.0.0.1:8080`。`/api/esp/stream` 保持持续 MJPEG 连接，浏览器关闭时取消上游，避免占满接收端观看名额。状态通过 WebSocket 更新，控制只允许本机同源 JSON 请求。

| 新 UI API | 接收端接口 |
| --- | --- |
| `GET /api/snapshot` | 汇总 `/status`、`/control`、`/detection`、`/transport` |
| `GET /api/esp/stream` | `/stream?camera=mipi` |
| `POST /api/mode` | `/control/route`，`mode: auto/direct/relay` |
| `POST /api/esp/camera` | `/control/camera`，`camera: mipi`、`enabled: boolean` |
| `POST /api/esp/detection` | `/control/detection`，`enabled: boolean` |

## 本轮验收

2026-11-19 在用户连接的 Tenda_LJS 局域网与两块实板上测试。新 UI 的原生画面尺寸为 1280×720，保留 180°旋转；浏览器脚本验证了人物检测开关、放大／Esc、320／375／414／768／1100／1440／1920 宽度布局与真实三维画布。测试使用 Edge 无头模式和 SwiftShader 软件渲染，性能数据受该测试环境影响。

网页成功完成直连到中继、暂停、暂停时切到直连、恢复、再切到中继，最终恢复自动模式。首轮两次切到中继的按钮等待时间约 6.1 秒和 8.0 秒，包含换网、心跳与图像确认，并非纯视频停顿时间。首轮 60.31 秒中继测量为接收 28.83 fps、MJPEG 转发 28.78 fps、最大转发帧间隔 1.328 秒，故继续降低三维示意开销后复测。最终结果见下方追加记录及原始 JSON；不得把这一轮描述为无卡顿或无缝切换。

降低场景开销后的最终 60.35 秒测量：接收 **26.38 fps**、MJPEG 转发 **26.35 fps**，全程 1280×720，中继路径；最大转发帧间隔 **1.969 秒**。没有离线采样，但短暂卡顿仍存在，帧号缺失率窗口峰值为 59%。因此 UI 功能验收通过不代表中继达到持续 30 fps。

关闭测试浏览器后的独立 30.05 秒对照：接收 26.29 fps、转发 26.32 fps、最大间隔 1.453 秒；推理与 Node 接收桥仍在运行。这一轮接收端和转发端速率接近，不能把停顿单独归因于三维页面。原始记录在 `buffer/render_checks/esp-receiver-baseline.json`；首轮记录另存 `esp-live-before-scene-tuning.json`。最终网页控制重新验证通过，结束时恢复自动模式。

自动检查命令：

```powershell
npm test
npm run build
npm run test:esp-ui
node scripts/check-flight-ui.mjs
node scripts/check-esp-live.mjs
```

`test:esp-ui` 和 `check-esp-live.mjs` 需要设备真实在线，会操作检测或路由开关。后者恢复自动模式；不要与其他控制测试并行运行。报告与截图在 `buffer/render_checks/esp-ui.json`、`esp-live.json`、`esp-relay-live.png`，日志在 `buffer/logs/`。单元测试另外覆盖断图／暂停清理、状态超时、命令参数与来源检查、失败 ACK，以及关闭观看时释放上游连接。

本次没有改动硬件固件，也没有复测远距离、多墙、长时间供电或新人的识别准确率。双摄像头及 A/B 双中继仍属于独立待实现方案。

无人机场景更新的实板检查另外记录在 `buffer/render_checks/flight-ui.json`：直连与中继各取 10 个位置样本，验证无人机持续飞行、保持高度 18，且位置符合当前圆心与半径；检查详情折叠、两侧栏收起／恢复，以及 320～1920 px 下主要标签的字号、裁切和重叠。单元测试核对强信号下半径仍有变化，以及不同渲染频率和半径下的匀速运动。实板脚本结束时恢复开始测试前的路由模式，不将界面示意当作真实无人机定位或实测距离。

另用 `node scripts/check-orbit-rssi.mjs` 在浏览器内注入 −33 → −35 dBm，确认强信号变化会使目标半径从 6.5433 增至 7.1035，实际半径平滑跟随，飞行相位不重置。该脚本不发送无线控制命令、不改接收端数据；结果只证明前端响应，不能用来证明无线测距精度。记录见 `buffer/render_checks/orbit-rssi-fixture.json`。信号引起的镜头缩放也使用平滑过渡。

## 园区渲染更新

实时模式使用 `CampusEnvironment.tsx` 中的园区模型，增加玻璃窗框、石材外墙、屋顶设备、入口雨棚、道路标线、停车位和树冠。无人机补充了云台镜头、起落架、独立桨叶与航行灯。材质颜色集中在 `scene-theme.ts`，反射环境和路面纹理均在本地生成，不依赖互联网。原有示例模式仍保留。

窗户和景观按材质合并为实例绘制；建筑阴影只在场景结构变化时更新。软件渲染会降低三维画布分辨率，硬件加速使用较高清晰度；摄像头仍为原生 1280×720。主标签保留清晰字号，窗口较窄时隐藏次要建筑标签。

运行 `node scripts/check-scene-quality.mjs` 检查布局和场景交互，运行 `node scripts/check-scene-stream.mjs` 采样约 20 秒的视频和浏览器动画。默认使用 SwiftShader，设置环境变量 `ESP_RENDER_HARDWARE=1` 后使用浏览器默认图形后端，并记录实际显卡名称。这两个脚本不发送切网、摄像头或人物检测控制命令。

2026-11-19 最终使用 RTX 4080 Laptop 的 D3D11 后端检查，320～1920 px 八种宽度、楼层展开、透明查看和视频放大均通过。场景报告 82 次绘制、36,022 个三角形、3 张纹理。20.18 秒的中继采样为 **30.73 接收 fps、1280×720、0 个离线采样**；该轮人物检测已处于关闭状态，脚本未修改它。浏览器动画回调约 119.77 次／秒，这不是独立呈现帧率或视频帧率，短测也不能证明持续无卡顿。原始记录见 `buffer/render_checks/scene-quality.json`、`scene-stream.json`；截图见 `scene-overview.png`、`scene-1440.png` 和 `scene-320.png`。
